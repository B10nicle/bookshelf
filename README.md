# Книжный шкаф

Публичный каталог русских IT-книг с личной библиотекой. Пользователь может искать книги по названию, автору и ISBN, отбирать темы и издательства, а также отмечать издания, которые уже есть в его коллекции.

Сайт: [b10nicle.github.io/bookshelf](https://b10nicle.github.io/bookshelf/)

## Возможности

- 170 русских изданий, объединённых в карточки произведений;
- поиск, тематические кнопки, фильтр издательства и сортировка;
- отдельный режим «В моей библиотеке»;
- вход по email и синхронизация отметок между устройствами;
- русские обложки через ImageKit CDN;
- проверка ISBN, тем, источников и ссылок на обложки при сборке.

## Стек

| Задача | Используется |
| --- | --- |
| Интерфейс | React 19, JavaScript, CSS |
| Сборка и локальная разработка | Vite 6 |
| Авторизация и личная библиотека | Firebase Authentication, Cloud Firestore |
| Обложки | ImageKit CDN |
| Тесты | Vitest, Testing Library, JSDOM |
| Проверка каталога | Python 3, Zod |
| Публикация | GitHub Pages, GitHub Actions |

## Локальный запуск

```bash
npm ci
npm run dev
```

Для проверки изменений:

```bash
npm test
npm run build
```

`npm run build` генерирует данные каталога, проверяет их и создаёт готовую к публикации папку `dist/`.

## Структура проекта

- `src/` — React-интерфейс, Firebase-клиент, фильтрация и тесты;
- `research/` — карточки изданий, правила группировки, исключения и манифест ImageKit;
- `covers/` — локальные исходники обложек для проверки;
- `public/` — статические XML-файлы и favicon;
- `tools/` — генерация каталога, валидация и загрузка обложек;
- `firebase/` — правила Firestore и инструкция по настройке;
- `.github/workflows/deploy-pages.yml` — автоматическая публикация.

## Данные и обложки

В опубликованном интерфейсе используются CDN-ссылки ImageKit. Локальные обложки в `covers/` нужны для проверки и подготовки новых данных.

Полный порядок добавления книг, включая проверку исключений, ISBN, издателя, обложки и публикацию, описан в [AGENTS.md](AGENTS.md).

## Публикация

Основная ветка — `main`. Каждый push в неё автоматически выполняет:

1. установку зависимостей;
2. тесты;
3. сборку и валидацию каталога;
4. публикацию `dist/` на GitHub Pages.

Не добавляйте в Git папки `node_modules/`, `dist/` и файлы с секретами. Firebase API-конфигурация для браузера не является секретом; закрытые ключи ImageKit должны оставаться только в локальном `.env`.
