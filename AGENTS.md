# Добавление книг в «Книжный шкаф»

Эта инструкция обязательна для любого агента, который добавляет или меняет книгу в каталоге.

## Навык проекта

Для добавления или обновления книги сначала прочитайте
[`skills/bookshelf-add-book/SKILL.md`](skills/bookshelf-add-book/SKILL.md).
Это переносимый пошаговый регламент: проверка ISBN и источника, подготовка
обложки, ImageKit, проверки и публикация. Правила ниже остаются источником
истины для этого репозитория.

## Главный принцип

В каталоге одна запись соответствует **конкретному ISBN и конкретному русскому изданию**. Не создавать запись только по названию, по англоязычному оригиналу или по приблизительному совпадению обложки.

Поля и обложки основной подборки должны соответствовать одному и тому же изданию. Если это не удаётся подтвердить, не добавляйте книгу в опубликованный каталог: заведите кандидат отдельно и попросите пользователя подтвердить данные.

## Порядок работы

1. Прочитайте `research/excluded-works.json` и убедитесь, что книга, её редакция или серия не запрещены пользователем. Запрет имеет приоритет над любым старым решением или новой находкой.
2. Проверьте дубликаты по нормализованному ISBN, названию и автору в:
   - `research/records.json`;
   - `research/user-additions-2026-11-17.json`;
   - `research/work-groups.json`.
3. Найдите первичный источник: страницу издательства предпочтительнее карточки магазина. Подтвердите минимум: русское название, авторов, издательство, год, ISBN и число страниц, если оно доступно.
4. Подберите тему из существующих кнопок: `java`, `spring`, `kotlin`, `scala`, `jvm`, `algorithms`, `ddd`, `hibernate`, `compilers`, `kafka`, `misc`.
   - Если книга действительно относится к нескольким темам, укажите несколько кодов.
   - Не добавляйте новую тему или кнопку без прямого запроса пользователя.
5. Получите русскую обложку именно этого ISBN. Обложка, присланная пользователем, допустима, но это необходимо отметить в `coverSource` и `verificationNotes`.
6. Создайте JPG-версию в `covers/<ISBN-без-дефисов>.jpg`. Вычислите SHA-256 и размеры файла. Исходник из `Desktop/images` не редактировать и не перемещать.
7. Добавьте объект в `research/user-additions-2026-11-17.json`. Для записи обязательны все поля из соседних объектов, включая:
   `url`, `title`, `publisher`, `authors`, `isbn`, `isbnNormalized`, `year`, `yearKind`, `pages`, `coverSource`, `coverSourceType`, `coverPath`, `width`, `height`, `sha256`, `coverVerification`, `visualVerification`, `topicCodes`.
8. Если это новое издание уже существующего произведения, добавьте ISBN в подходящую группу в `research/work-groups.json`. Не объединяйте разные книги только из-за похожего названия.
9. Загрузите обложку в ImageKit, а затем убедитесь, что `research/imagekit-manifest.json` содержит публичный URL по ключу ISBN. Публикуемая React-версия должна брать картинку по этой CDN-ссылке, не из локальной папки `covers/`.
10. Пересоберите, проверьте и опубликуйте каталог.

## ImageKit: безопасная загрузка

Никогда не записывайте ключи в JSON, JavaScript, Git, README, историю команд или ответ пользователю. Не используйте секрет, ранее присланный в чат: для каждой сессии пользователь должен передать действующий временный ключ или самостоятельно выполнить загрузку.

Локальный файл `.env` (он игнорируется Git) может содержать только на время операции:

```sh
IMAGEKIT_PRIVATE_KEY=…
IMAGEKIT_URL_ENDPOINT=https://ik.imagekit.io/bookshelf
```

Для загрузки всех отсутствующих обложек используйте:

```sh
set -a; source .env; set +a
python3 tools/upload-imagekit.py
```

После успешной загрузки удалите `.env` или удалите из него `IMAGEKIT_PRIVATE_KEY`. При добавлении одной книги скрипт безопасно пропускает ISBN, которые уже есть в манифесте.

## Проверка и публикация

Из корня репозитория выполнить:

```sh
npm run build
```

Перед публикацией локально выполните `npm test` и `npm run build`; GitHub Actions повторит обе проверки автоматически.

Сборка должна завершиться без ошибок. Она одновременно:

- валидирует ISBN, целостность и размеры обложек;
- обновляет XML;
- генерирует `src/catalog-data.json` для React;
- проверяет уникальность ISBN, темы, HTTPS-источники и ImageKit CDN-обложки;
- создаёт готовую папку `dist/`.

Перед публикацией проверьте новую запись в `src/catalog-data.json`: ISBN, название, авторы, выбранная тема и `coverUrl` должны быть верны; `coverUrl` обязан начинаться с `https://ik.imagekit.io/bookshelf/`.

Основная ветка `main` содержит исходный код. После push в `main` GitHub Actions сам устанавливает зависимости, запускает тесты, создаёт `dist/` и публикует сайт через `.github/workflows/deploy-pages.yml`. Не коммитьте `dist/` или `ghpages/`: это временные результаты сборки. После push дождитесь успешного выполнения workflow Deploy GitHub Pages.

## Что сообщать пользователю

Кратко укажите: добавленную книгу, тему, издательство/год/ISBN, что используется обложка из ImageKit, и ссылку на опубликованный сайт. Если не хватает библиографических данных или ключа ImageKit — прямо назовите единственное недостающее действие; не подставляйте догадки.
